# Cómo contribuir

RRUU recibe problemas antes que soluciones cerradas. Una buena propuesta explica:

1. qué problema regional existe;
2. quién lo experimenta y en qué lugares;
3. qué evidencia lo demuestra;
4. qué resultado pequeño permitiría aprender;
5. cómo sabríamos si funcionó.

Usa el formulario **Propuesta de proyecto** en GitHub. La revisión pública puede pedir aclaraciones, vincular propuestas duplicadas o recomendar una investigación previa. La aceptación de una propuesta no garantiza financiación; autoriza incorporarla a la hoja de ruta y buscar un responsable.

## Proceso actual de una propuesta

1. **Registrar:** cualquier persona abre un Issue mediante el formulario de propuesta.
2. **Aclarar:** la comunidad pide evidencia, define quién vive el problema y comprueba que no exista ya otro expediente.
3. **Clasificar:** se decide si es una tarea, una decisión, una investigación o una iniciativa con alcance de proyecto.
4. **Revisar:** se comprueba su compatibilidad con los principios de RRUU, riesgos, dependencias y condición de éxito.
5. **Incorporar:** si se acepta como proyecto, se asignan responsable, etapa estratégica y ciclo participativo en GitHub Projects.
6. **Deliberar y decidir:** cuando la propuesta requiere una decisión colectiva, se publica información neutral y se abre la consulta o votación correspondiente.
7. **Ejecutar y verificar:** el responsable publica hitos; al final se compara el resultado con la condición de éxito.

El número automático del Issue es el identificador público. RRUU no mantiene por ahora una numeración paralela.

## Cuándo crear un proyecto

Una propuesta se convierte en proyecto cuando cumple al menos una de estas condiciones:

- persigue un resultado importante que requiere varias tareas o contribuyentes;
- continuará durante varios hitos o necesita mantenimiento recurrente;
- requiere un responsable claro, coordinación, recursos, datos o gestión de riesgos;
- contiene varias decisiones, investigaciones o entregables relacionados;
- su progreso debe formar parte visible de la hoja de ruta de RRUU.

No se crea un proyecto nuevo para una corrección editorial, un error aislado, una pregunta de investigación pequeña o una mejora de una sola entrega. Ese trabajo permanece como Issue o sub-issue del proyecto existente.

Un proyecto aceptado conserva un **Issue principal** como expediente público. Las tareas menores se enlazan como sub-issues; GitHub Projects ofrece la vista operativa de estado y etapa.
